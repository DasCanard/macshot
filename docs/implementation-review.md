## Streaming GIF follow-up

It retains only the previous pixels and pending encoded frame. The container uses local palettes, actual presentation-time delays, a full first frame, changed rectangles for later frames, and unchanged-pixel coalescing. Long holds split at the format's 16-bit delay limit. Format reference: [GIF89a specification](https://www.w3.org/Graphics/GIF/spec-gif89a.txt).

## Cadence correction for long, sparse recordings

- The first endurance file also exposed an export inefficiency: its nominal rate was **15.484 fps** across active/idle intervals, while its shortest sample lasted **13.45 ms**. Treating that minimum as the render interval selected **74.349 fps** for a capture configured at 30 fps. Neither a whole-file average nor one shortened tail describes active motion. Apple's [minimum-frame-duration definition](https://developer.apple.com/documentation/avfoundation/avassettrack/minframeduration) describes the shortest interval, not an intended render cadence.
- `VideoFrameCadence` now writes an explicit rational interval into MP4's supported software metadata field (`macshot; frame-duration=1/30`). An initial arbitrary QuickTime metadata key was silently dropped by MP4 writing; round-trip tests caught it, and that implementation was replaced. The supported [software identifier](https://developer.apple.com/documentation/avfoundation/avmetadataidentifier/commonidentifiersoftware) round-trips through recording, transcoding, export sessions and audio mixing. Invalid/unrelated values are ignored. New captures retain their intended interval even if almost entirely static.
- Unmarked/older inputs receive a bounded background inspection of at most **1,152** presentation intervals at nine positions, without decoding pixels or scanning every frame. This is an inference for imported VFR media, not proof of every cadence in an arbitrary movie. A very brief unsampled motion section can still evade the bounded inspection. ## Transactional screenshot history and editor saves

- Replaced history's independent image/index writes with `HistoryImageSnapshot` and a serial `HistoryStorage` owner. The main actor snapshots separately owned pixels for both composited and raw images, and serializes annotation/edit data before enqueueing; mutable AppKit images no longer cross the encoding queue. ImageIO writes PNGs off the main thread. Each save creates a fresh UUID revision containing its full matching image/sidecar set, flushes the files, then atomically publishes the index. Failed publication preserves the prior revision and index byte for byte. Legacy flat files remain readable and migrate when an edit successfully commits. Downgrade compatibility with the old flat-file-only reader and crash-orphan recovery UI are not established.
- Save, remove, clear and retention operations share the same queue. History exposes only committed rows. Pending identifiers are returned directly to capture callers, so disabled/asynchronous history cannot accidentally associate a new capture with the previous row. Optimistic deletion is restored if index publication fails; queued old writes cannot resurrect a subsequently cleared row. Exact obsolete revision paths are cleaned only after the main actor adopts the new index. Quit waits for publication and cleanup.
- Editor Done and Save & Close now close only after a successful save of the current edit state. A failure keeps the editor open; editing while a save runs leaves the newer state dirty. Output actions capture a matching image, cloned annotations, edit state and revision before any asynchronous file-save callback. Older callbacks cannot submit over a newer history save. When history is disabled, explicit Save & Close uses the normal file-save destination/sheet. Scroll notification observers are removed on editor close instead of accumulating orphaned block observers. General image-file encoding, all image/upload quit coordination and ordinary undo-branch dirty-state detection remain open.
- History previews resolve immutable revision URLs on the main actor and decode at most 480 pixels with ImageIO on workers. AppKit images are created back on the main actor. Cache entries and in-flight tokens are invalidated when a revision changes, so an old callback cannot overwrite the edited preview or clear a newer request. PNG originals retain pixel and point sizes; the menu/grid caches carry enough pixels for Retina without full-size fallback decoding.
- Eleven new transaction tests cover queued ownership of both images and annotation values, pixel preservation, clear racing queued writes, byte-for-byte rollback of image/raw/annotation/index files, deletion failure, invalid image data, disabled history IDs, serialized revisions, legacy migration, visible new-save failure, Retina sizing and bounded legacy preview decoding.
